# 联机改造说明（单人 → 2 人局域网合作）

本工程原本是一个 Unity 2022.3 的**单人 2D 横版魂系 RPG**。
这次改造把它变成了**局域网 2 人合作**，同时**完整保留单机玩法**：
不点联机按钮，游戏和改造前一模一样。

---

## 一、5 分钟上手

### 1. 等 Unity 把包装好
改造引入了官方网络库，`Packages/manifest.json` 里已加：

```
"com.unity.netcode.gameobjects": "1.12.0"
```

打开工程时 Unity 会自动下载它（依赖 `com.unity.transport` 会自动带上）。
如果 Package Manager 报错，手动装一次：
**Window → Package Manager → + → Add package by name → 输入 `com.unity.netcode.gameobjects` → 版本 `1.12.0`**

### 2. 执行一键配置（只需要一次）
菜单栏：

```
Tools → 联机改造 → ① 一键配置联机场景
```

它会自动完成（可重复执行，不会重复挂组件）：

| 做的事 | 说明 |
| --- | --- |
| 生成 `Assets/Resources/Multiplayer/Player_Multiplayer.prefab` | 由场景里的 Player 复制而来，挂上 `NetworkObject` / `OwnerNetworkTransform` / `PlayerNetwork` / `NetworkCharacterStats` |
| 给 `ItemObject_空.prefab`、`LostCurrency.prefab` 补网络组件 | 掉落物、掉落的灵魂可以被双方看到 |
| 给 `MainScene` / `MainPass1` 里所有敌人补网络组件 | `NetworkObject` + `NetworkTransform` + `NetworkCharacterStats` + `EnemyNetwork` |
| 给场景里所有存档点补网络组件 | `NetworkObject` + `WorldObjectNetwork` |
| 在玩家原位置放锚点 + 2 个出生点 | 避免两个玩家叠在一起 |
| 在 `Main Menu` 场景放 `NetBootstrap` | 登记需要联网同步的预制体 |

### 3. 自检
```
Tools → 联机改造 → ② 联机自检
```
全绿（Console 输出「全部通过 ✅」）就可以玩了。

### 3.5 中文显示（重要）
工程的 TMP 默认字体是 `LiberationSans SDF`，**只有拉丁字形**；
`TMP Settings` 的 fallback 列表是**空的** —— 所以中文会显示成 `□□□`。

工程里其实有两样相关资源，但**都不能直接用**：

| 资源 | 实际情况 |
| --- | --- |
| `Assets/Graphics/Font/字体/msyh.ttc`<br>`SourceHanSansSC-Regular.otf` | 这是**字体文件**，TMP 不能直接用，必须先烘焙成 TMP 字体资源（`.asset`） |
| `SIMSUN SDF.asset` | 只烘焙了 **123 个字符**（就是 `字体.txt` 里那些标点），显示中文会大面积方块 |
| `我的字体.asset` | Static 模式、**8192×8192 × 25 页**图集（文件 130MB，显存约 1.5GB），为了一个菜单加载它代价太大 |

所以一键配置的第 2 步会自动执行 **③ 生成中文字体资源**：
从 `msyh.ttc`（微软雅黑，失败则退回思源黑体）生成一个**动态图集**的 TMP 字体资源：

```
Assets/Resources/Multiplayer/Fonts/Chinese SDF.asset
```

动态图集只占一张 1024×1024，**用到哪个字才生成哪个字**，两万多个汉字都能显示，
也不会有"某个字没烘焙所以是方块"的问题。

运行时 `ChineseFontSupport` 会把它挂到 TMP 默认字体的 fallback 链上，
所以不只是联机面板，**原有界面的中文（技能名、飘字、道具描述、"你死了"）也会一起被修好**。

> 这一步没跑也没关系：运行时会自动改用系统里的中文字体（微软雅黑等）动态生成，
> Windows 上照样能正常显示。跑一次是为了打包出去之后也自包含。
> 手动重跑：`Tools → 联机改造 → ③ 生成中文字体资源`

### 4. 开玩
见下面第二节，那里有完整的「自己测通 → 和同 WiFi 的朋友玩 → 和朋友跨网络玩」流程。

## 二、怎么和朋友一起玩

### 第 0 步：先自己测通（最重要，5 分钟）

**不要一上来就喊朋友**，先用一台电脑把流程跑通，这样出问题能立刻定位。

同一台电脑不能开两个 Unity 编辑器（同一个工程只能被一个编辑器打开），所以：

1. **打包一次**：`File → Build Settings` → 确认列表是
   `0: Main Menu` / `1: MainScene` → **Build** 到一个空文件夹。
2. **双击 exe 开第一个窗口** → 点 **创建房间（我是房主）**。
3. **再双击一次 exe 开第二个窗口** → 地址栏保持 `127.0.0.1` → 点 **加入房间**。
4. 判断成功：两个窗口里都能看到**两个角色**，各自用键鼠控制，能一起打同一只怪，
   一只怪死了两边同时倒。

> 也可以「Unity 编辑器当房主 + 打包的 exe 当客户端」，效果一样。
> `127.0.0.1` 意思就是"本机"，所以同一台电脑的两个进程能直接连上。

这一步通了，说明联机逻辑、预制体、场景配置全对，接下来只是网络环境问题。

### 第 1 步：局域网（同一个 WiFi / 同一个路由器）—— 最简单

1. **房主**：开游戏 → 点 **创建房间**。
   面板上会显示 `本机 IP（告诉朋友）：192.168.x.x`，点上方的
   **「复制本机 IP（发给朋友）」** 按钮直接复制发给朋友。
2. **朋友**：开游戏 → 在地址框里填这个 IP → 点 **加入房间**。
3. 双方进入同一关卡。

> 房主**不需要**在地址框里填任何东西（点了「创建房间」根本不读那个框）。
> 地址框只对「加入的人」有意义。以前把这个搞混，导致房主绑定了非法地址。

**必须做的两件事：**

- **两台机器在同一个网段**（都是 `192.168.1.x` 或都是 `192.168.0.x`）。
  连着同一个路由器 / 同一个手机热点就算同一个局域网。
- **房主放行防火墙**。第一次点"创建房间"时 Windows 会弹窗问是否允许网络访问，
  一定要勾**专用网络**并允许。如果手滑点了取消，用管理员身份打开 PowerShell 执行一次：

  ```powershell
  New-NetFirewallRule -DisplayName "OurRPG 联机" -Direction Inbound -Protocol UDP -LocalPort 7777 -Action Allow
  ```

- 如果朋友填了 IP 但一直卡在「正在连接」，先让房主在自己机器上试 `127.0.0.1`，
  能连上就说明是防火墙 / 网络环境问题，而不是游戏问题。

### 第 2 步：朋友在别的地方（不在同一个 WiFi）

当前实现是**直连 IP**，跨网络必须解决「怎么让外部访问到房主」这个问题。三种办法：

| 办法 | 难度 | 说明 |
| --- | --- | --- |
| **虚拟局域网工具**（ZeroTier / Tailscale / 蒲公英，**推荐**） | 低 | 双方装好、加入同一个虚拟网络，就相当于连进了同一个局域网。然后**照第 1 步做**，只是地址填虚拟网卡的 IP（Tailscale 是 `100.x.x.x`，ZeroTier 是 `10.147.x.x`） |
| **路由器端口映射** | 中 | 在路由器后台把 **UDP 7777** 转发到房主的内网 IP；朋友填房主的**公网 IP**（百度搜"IP"可查）。缺点：需要路由器管理权限，而且如果公网 IP 是 `100.64.x.x` 这类运营商级 NAT，映射了也没用 |
| **Unity Relay 中继** | 高 | 不用开端口，但需要接 Unity Gaming Services、注册项目、改代码。目前**没有**接 |

> 结论：想今天就和异地朋友玩，装个 Tailscale 最省事；把对方当"同一个 WiFi"处理。

### 端口

默认 **UDP 7777**（`NetBootstrap` 的 `port` 字段可改）。
改的话**房主和客户端必须改成同一个**——客户端目前用的是自己 `NetBootstrap` 上的 port，
所以两边都要改。

### 联机时和单机的区别

游戏内按键和原来完全一致（A/D 移动、空格跳、鼠标左键攻击、Shift 冲刺……），
每个玩家**只用自己机器上的键鼠**控制自己的角色。

| 场景 | 行为 |
| --- | --- |
| 自己死亡 | 弹出死亡界面，点按钮 → **原地在最近的存档点复活**（不再重开整关，另一个玩家不受影响） |
| 队友死亡 | 你能看到他的尸体倒下，自己游戏不受影响 |
| 打开菜单 / 背包 | 只暂停自己的画面，**不会冻结队友**，也不会卡住网络 |
| 打怪掉魂 | 灵魂归**最后一击的人** |
| 捡道具 | 谁先碰到归谁，道具在双方画面里同时消失 |
| 存档点 | 服务器统一激活，双方看到的激活状态一致 |

## 三、架构：谁说了算

多人游戏最难的是「谁有这个数据的权威」。本改造采用**混合权威**，
在「手感」和「实现成本」之间取平衡：

| 数据 | 权威方 | 原因 |
| --- | --- | --- |
| 玩家移动 / 跳跃 / 冲刺 | **各自的客户端**（Owner Authority） | 保留原来的 Rigidbody2D 手感，不需要做客户端预测 |
| 玩家动画状态 | 各自的客户端 → 广播状态名 | 原生 Animator 逻辑完全没动 |
| 敌人 AI / 寻路 / 攻击判定 | **服务器（房主）** | 两个玩家看到同一批怪、同样的行为 |
| 敌人位置 | 服务器 → 客户端同步 | 同上 |
| 血量 / 死亡 / 元素状态 | **服务器** | 只有一个答案，不会出现「我这边怪死了你那边还活着」 |
| 伤害数值计算 | 攻击方的客户端算 → 交给服务器扣血 | 原来的暴击/闪避/元素公式**一行没改** |
| 货币 / 背包 / 技能树 / 设置 | **各自的客户端**（各自存档） | 每个人的进度属于自己的 |
| 存档点 / 道具拾取 / 掉落物 | 服务器 | 世界是共享的 |

> 这是「信任客户端」的合作模型：适合和朋友一起玩，
> 不适合开公开服务器对抗作弊。要升级成完全服务器权威，
> 需要把伤害公式搬到服务器并加入客户端预测，属于下一个阶段的工作。

### 关键文件

| 文件 | 作用 |
| --- | --- |
| `Assets/Scripts/Multiplayer/NetGame.cs` | 联机状态总入口（`IsOnline` / `IsServer` / `LocalPlayer`）。**业务代码只通过它判断联机** |
| `NetBootstrap.cs` | 创建/加入房间、断线处理、场景切换，自动创建 `NetworkManager` |
| `MultiplayerMenuUI.cs` | 纯代码构建的联机面板，不需要手动摆 UI |
| `PlayerNetwork.cs` | 玩家身份、所有权、动画同步、货币、死亡与复活 |
| `NetworkCharacterStats.cs` | 血量 / 死亡 / 元素状态的 `NetworkVariable` 同步 + 伤害 RPC |
| `NetCombat.cs` | 战斗结算唯一出口（单机时直接调原函数） |
| `EnemyNetwork.cs` | 敌人：服务器模拟 + 位置/动画/血量同步 + 击杀奖励 |
| `NetItemObject.cs` / `NetSpawn.cs` | 掉落物的服务器生成与 itemId 同步 |
| `WorldObjectNetwork.cs` | 存档点激活、世界物件销毁的服务器权威 |
| `MultiplayerSceneBootstrapper.cs` | 联机时自动禁用场景里「单机版」的 Player |
| `Editor/MultiplayerSetupTool.cs` | 一键配置 + 自检工具 |

| `Enemy_DeathBringer.cs` / `ThunderStrike_Control.cs` | 同上 |

## 五、排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 编译报错找不到 `Unity.Netcode` | 包装没装好，看第一节第 1 步 |
| 面板不出现 | 确认当前场景名字里有 `menu` / `菜单`；面板只在主菜单场景生成 |
| **中文显示成 □□□** | 字体缺中文字形。执行 `Tools → 联机改造 → ③ 生成中文字体资源`。运行时也会自动用系统中文字体兜底 |
| 点「创建房间」没反应 | 看 Console。端口 7777 被占用就改 `NetBootstrap` 的 `port` |
| **`Invalid network endpoint: 192.168.x.x/10.x.x.x:7777`** | 已修复：房主不再拿地址框里的内容去绑定（房主固定监听 `0.0.0.0`）。如果还报，说明用的是旧代码，重新打包 |
| **`Network listen address (...) is Invalid!` + `Host is shutting down`** | 同上，地址框里被填了非法内容。现在点「创建房间」根本不读地址框 |
| **`The referenced script (Unknown) on this Behaviour is missing!`** | 指的是敌人身上的 `NetworkTransform`（NGO 包里的脚本）。GUID 我核对过是正确的，通常是第一次导入包时的瞬时提示。若持续出现：在 `MainScene` 里选中一个敌人，看 Inspector 上有没有 `Missing (Mono Script)` 组件，有就重跑「① 一键配置」 |
| **一直卡在「正在连接…」** | ① 房主防火墙没放行（最常见）② IP 填错 ③ 两台机器不在同一网段 ④ 跨网络但没做端口映射 / 虚拟局域网 |
| 对方连不上 | ① 两台机器同一局域网 ② 防火墙放行 UDP 7777 ③ IP 填的是房主的**局域网 IPv4**，不是 127.0.0.1 |
| 房主自己能连 127.0.0.1，朋友连不上 | 说明游戏没问题，是网络环境：查防火墙 + 网段 + 是否跨公网 |
| 连上了但对面角色不动 | 玩家预制体缺 `OwnerNetworkTransform`（位置不会同步）→ 跑自检 |
| 进去后有两个一样的自己 | 一键配置没执行，或场景里的旧 Player 没被禁用 → 重新执行「① 一键配置」 |
| 进入关卡后立刻掉回主菜单 | `MainScene` 没加到 Build Settings → `File → Build Settings` 里加进去 |
| 看不到队友 | 检查 Console 有没有 `[联机] 场景里有 N 个敌人还不是网络对象` 的警告 |
| 敌人不动 / 浮空 | 一键配置没给敌人挂 `NetworkObject` + `EnemyNetwork` |
| 血量不同步 | 玩家预制体缺少 `NetworkCharacterStats` → 跑一次自检 |
| 队友走路很卡 | 提高 `OwnerNetworkTransform` 的 `Interpolate`，或在 `NetBootstrap` 里把 `NetworkConfig.TickRate` 调高 |

## 六、已知限制（下一步可以做的）

1. ~~技能特效只在本机显示~~ —— **已修复（v2）**。
   剑 / 黑洞 / 水晶 / 分身现在双端可见。做法是「表现副本」：
   施法者本地照旧生成并模拟（原有逻辑一行没改），生成后广播
   「什么技能 / 在哪 / 朝向 / 几个参数」；队友本地实例化同一个预制体并挂上
   `SkillFxVisualOnly`，外观、飞行、动画都一样，但**不结算任何伤害**
   （伤害仍只由施法者经 `NetCombat` 提交给服务器，不会翻倍）。
   关键代码：`Assets/Scripts/Multiplayer/NetSkillFx.cs` + `PlayerNetwork.SkillFxClientRpc`。
   顺带修了一个真 bug：客户端施放黑洞时，冻结现在会通过
   `NetworkCharacterStats.SetFrozenServerRpc` 传给服务器，
   之前客户端放黑洞服务器上的敌人其实照样在动。
   仍存在的细节差异：队友看到的是独立模拟的同款特效，剑的弹射/穿透次数
   没有完整同步（运动轨迹基本一致）；旋转剑、黑洞、水晶、分身完全一致。
2. **敌人攻击动画的 `Trigger` 参数**（例如眩晕的 `StunFold`）没有同步，
   远程玩家看到的眩晕表现可能略有差异。
3. **部分道具被动效果**（雷霆一击、冰火双刀等）在命中时只在本机播放特效。
4. **玩家死亡掉落装备**（`PlayerItemDrop`）在联机模式下暂未启用，
   目前只掉落灵魂，避免把队友的装备丢到地上。
5. **作弊**：伤害数值由客户端计算，只适合和信任的朋友一起玩。
6. **公网联机**：目前是局域网/直连。要上公网需要 Relay 或端口映射，
   NGO 可以接 Unity Relay 服务，属于额外配置。
7. **`MainPass1.unity`** 没有被加进 Build Settings（原本就没有），
   如果要在正式构建里用它，请在 File → Build Settings 里加进去。

## 七、想改成 3-4 人？

架构已经支持多人，只需要：

1. `NetBootstrap` 的 `maxPlayers` 改成想要的人数。
2. 场景里多放几个 `MultiplayerSpawnPoint`（或者直接靠自动生成的兜底出生点）。
3. 如果要做分屏，还需要额外给每个玩家分配独立的 Camera 和 Canvas。

UI 目前是「每个人一套自己的界面」，加人不需要改 UI。

## 八、自测清单（按阶段走，不要跳）

每一步都先 `Console → Clear` 再开始，这样看到的报错一定是本次的。

### 阶段 0 · 先确认 Console 是干净的
点 Play 之前清空 Console。之前那条
`The referenced script (Unknown) on this Behaviour is missing!`
如果是旧消息，清空后就不该再出现；如果**每次进场景都复现**，
在 `MainScene` 里选中一个敌人，看 Inspector 有没有 `Missing (Mono Script)`。

### 阶段 1 · 单机回归（证明改造没破坏原版）
`Main Menu` → Play → **什么都不点联机按钮** → 走原版「新游戏」流程。

| 应该看到 | 不该看到 |
| --- | --- |
| 进入关卡，**只有 1 个角色** | 两个一样的角色 |
| 能走、能跳、能打、技能正常 | `[NetBootstrap]` 开头的任何日志 |
| Console 无红字 | 敌人站着不动 / 浮空 |

### 阶段 2 · 只当房主（单开也要正常）
`Main Menu` → Play → 点 **创建房间**。

| 检查 | 期望 |
| --- | --- |
| 是否进关卡 | 自动进入 `MainScene` |
| 角色数量 | **只有 1 个**（多了说明场景旧 Player 没禁用） |
| 面板状态 | `房间已创建 ✅`，并显示一个 IP |
| 敌人 | 会追你、会打你，位置连续不抖 |
| Console | 不应有 `Invalid network endpoint` / `is Invalid` |

> 如果失败后**自动退回主菜单**了，这是设计好的：说明开服失败，看 Console 上面的报错。

### 阶段 3 · 本机双开（最关键）

有两条路，**建议先走 3B**（不依赖打包，能立刻判断联机逻辑对不对）。

#### 3A · 编辑器当房主 + 打包 exe 当客户端（最终形态）

1. `File → Build Settings → Build` 打一个 exe
2. **房主**：Editor 点 Play 当房主
3. **客户端**：打 exe，地址保持 `127.0.0.1` → 点 **加入房间**

打包后还支持**命令行直接开局**，省去两边点按钮：

```
MyRBG-test.exe -host              :: 直接当房主
MyRBG-test.exe -join 127.0.0.1    :: 直接当客户端（会自动重试 12 次）
MyRBG-test.exe -host -port 8000   :: 换端口
```

客户端带重试，所以**先开房主还是先开客户端都无所谓**。
（编辑器里运行会自动忽略这些参数。）

#### 3B · 两个编辑器（不依赖打包，用来单独验证联机逻辑）

编辑器加载场景走的是资源库，**不经过打包出来的 `level1`**，
所以这条路能把「联机逻辑问题」和「打包数据问题」彻底分开。

1. 新建一个目录，例如 `D:\unitycod\MP-client`
2. 把这三个目录**复制**过去（约 0.28 GB，不要带 `Library`）：
   `Assets`、`Packages`、`ProjectSettings`
3. 用 Unity Hub 打开 `D:\unitycod\MP-client`（首次会导入资源，几分钟）
4. 两个编辑器都打开 `Main Menu` 场景：
   - 原工程：Play → 点 **创建房间**
   - 复制的工程：Play → 地址填 `127.0.0.1` → 点 **加入房间**

> 两个工程的 `Assets` 是同一份拷贝，`.meta` 里的 GUID 完全一致，
> 所以玩家预制体的网络 ID 也一致，可以正常互通。

**判断结果：**
- **3B 通了** → 联机逻辑没问题，问题 100% 在打包序列化，专心修 3A
- **3B 也不通** → 是联机逻辑的问题，把 Console 第一次出现的红字发出来

#### 双开后逐项核对

| 检查 | 期望 |
| --- | --- |
| 两边角色数 | 都是 **2 个** |
| 对方移动 | 对面角色跟着走，动画不僵住、不滑行 |
| 朝向 | 对面角色转身方向正确 |
| 打怪 | 两边血条**同时**下降，怪物两边同时倒地 |
| 灵魂 | 谁打死的归谁（面板数字） |
| 掉落物 | 怪死了掉的东西两边都看得见，谁捡谁得 |
| 存档点 | 一人点亮，另一边也亮 |
| 死亡 | 自己死了点按钮 → 原地复活；队友完全不受影响 |
| 打开背包/菜单 | 只有自己画面暂停，队友照常动 |
| 退出 | 停止 Play 出现 `客户端 1 已离开` 是**正常**的 |

### 阶段 4 · 局域网真人
见第二节。房主点「复制本机 IP（发给朋友）」，对方填进去加入。

### 报错对照
把 Console 里**第一次**出现的红字发出来就够了（后面的通常是连锁反应）。
现在关键的失败点都会带明确前缀：`[NetBootstrap]` / `[中文字体]` / `[联机]`。
